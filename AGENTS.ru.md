# Правила репозитория

Русский перевод [Repository Guidelines](AGENTS.md).

## Структура проекта и модулей

CLI на Python и логика метрик находятся в `src/ub_mode_php/`; AST-парсер, который не изменяет исходный код, и манифест Composer — в `php/analyzer/`. `bin/ub-php` запускает команду. Тесты Python расположены в `tests/`, тесты PHP — в `php/analyzer/tests/`, небольшие проекты с образцами синтаксиса — в `fixtures/`. Протокол и метрики описаны в `docs/`. Необязательный скилл и примеры интеграции для агентов находятся в отдельном репозитории `ub-mode-php`. Локальный каталог `work/` содержит материалы для передачи задач и исключён из Git в этой рабочей копии.

## Сборка, тестирование и разработка

Используйте Python 3.12+ и PHP 8.2+. Из корня репозитория выполните `python -m pip install -e '.[dev]'` для установки CLI и инструментов тестирования Python, затем `composer install --working-dir=php/analyzer` для установки парсера. Запускайте `python -m pytest` и `composer test --working-dir=php/analyzer`. Команда `ub-php doctor` проверяет окружение; `ub-php check --format json` анализирует настроенные пути PHP. Если локальных сред выполнения нет, `docker build -t ub-cdmu-php:dev .` собирает автономный образ. Пример команды с подключённым проектом приведён в [README на русском](README.ru.md).

## Стиль кода и соглашения об именах

Используйте четыре пробела в Python и стиль PSR-12 в PHP. Имена модулей и функций Python пишите в `snake_case`, классов PHP — в `PascalCase`. Оставляйте чистые расчёты метрик в Python, а извлечение AST — в PHP; через границу между ними передавайте только версионированный JSON. Сохраняйте стабильный порядок в отчётах и проверяйте внешние данные до расчёта метрик. Не выполняйте и не изменяйте анализируемый PHP-код.

## Тестирование

Тесты Python используют pytest, тесты PHP-анализатора запускаются скриптом Composer `test`. По возможности добавляйте тест поведения для изменений в разборе кода, выводе CLI, правилах метрик или протоколе до реализации. Делайте образцы фреймворков минимальными. Обязательный процент покрытия тестами не задан; отсутствующее покрытие Clover должно оставаться `unknown`. Стандартный порог известного CRAP — `< 10`; кандидаты Dryer считаются предупреждениями.

## Коммиты и запросы на слияние

Пишите короткие сообщения коммитов в повелительном наклонении. В запросе на слияние объясните изменение поведения, укажите связанную задачу или раздел спецификации, выполненные тесты и изменения зависимостей или JSON-протокола. При изменении отчёта приложите пример JSON. Не включайте в коммиты сгенерированный каталог `.metrics/`, Composer `vendor/` и локальные файлы IDE.
