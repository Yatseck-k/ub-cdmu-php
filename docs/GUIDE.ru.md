# CDMU: простая инструкция

[English version](GUIDE.md)

CDMU (`ub-php`) проверяет качество PHP-кода, не запуская его:

- **CRAP** — насколько функция сложна и насколько она не покрыта тестами. Чем больше число, тем рискованнее менять этот код. Порог по умолчанию — 10.
- **DRY** — пары похожих функций, которые, возможно, стоит объединить.
- **Мутации** (по желанию) — проверяют, замечают ли ваши тесты намеренные поломки кода.
- **UML** (по желанию) — страница со схемой классов и связей, открывается в браузере без сервера.

Полные подробности — в [руководстве](README.ru.md). Эта страница — быстрый старт.

## Что нужно

- PHP 8.2+ и Composer 2 (расширения `dom`, `json`, `mbstring`).
- Git — только для флага `--changed`.
- Для мутаций дополнительно: Infection 0.29.14, PHPUnit, драйвер покрытия (Xdebug или PCOV), расширения `posix` и `pcntl` (Linux/macOS).

## Установка

Из корня вашего PHP-проекта (пока пакет не опубликован — через локальную копию):

```sh
composer config repositories.ub-cdmu-php path /путь/к/ub-cdmu-php
composer require --dev yatseck-k/ub-cdmu-php:@dev
vendor/bin/ub-php doctor
```

`doctor` должен показать `php_supported: true` и вернуть код 0. Все команды ниже запускайте из корня проекта.

Анализатор ищет код в каталогах `src` и `app`. Если их нет, создайте `.ub-mode.yaml` (см. [настройку](#настройка)).

## Первый запуск

```sh
vendor/bin/ub-php check
```

Команда разбирает код, считает CRAP и ищет дубликаты. Результат — одна из трёх строк:

| Итог | Код выхода | Что значит |
| --- | --- | --- |
| `PASS` | 0 | Замечаний нет |
| `WARN` | 0 | Есть предупреждения: покрытие неизвестно, найдены похожие функции или нет изменённых файлов |
| `FAIL` | 2 | Известный CRAP достиг порога |

Отчёты сохраняются в `.metrics/` (`check.json`, `crap.edn`, `dry.edn`); добавьте `.metrics/` в `.gitignore`. Внизу вывода есть блок «Next steps» с подсказками.

Полезные флаги: `--verbose` — показать все записи, `--progress never` — без полосы прогресса.

## Почему везде «unknown»

CRAP считается по покрытию тестами. Пока готового отчёта нет, покрытие **неизвестно** — это не 0% и не «всё хорошо». Получите отчёт Clover тестами проекта (нужен Xdebug или PCOV) и запустите проверку снова:

```sh
XDEBUG_MODE=coverage vendor/bin/phpunit --coverage-clover coverage.xml
vendor/bin/ub-php check
```

Файл `coverage.xml` в корне проекта подхватывается автоматически; другой путь задаётся в `crapper.coverage.path`. Пути внутри отчёта должны указывать на файлы вашего проекта: отчёт, созданный в контейнере с другими абсолютными путями, не сопоставится.

## Что делать с результатом

- **CRAP выше порога** — упростите ветвления в функции, добавьте тесты или сделайте и то, и другое. Не повышайте порог, чтобы убрать замечание.
- **DRY-кандидаты** — это только предупреждения. Сравните смысл функций: сходство структуры не значит, что код нужно объединять. Более строгая проверка: `vendor/bin/ub-php dry --threshold 0.8`.
- **Только свои изменения:**

  ```sh
  vendor/bin/ub-php check --changed
  ```

  Берутся изменённые, индексированные и новые PHP-файлы из `src`/`app`. Нужен Git-репозиторий; вне Git запускайте без `--changed`. Пустой результат по изменениям не говорит о качестве всего проекта.

## JSON и CI

```sh
vendor/bin/ub-php check --format json > result.json
```

Решения принимайте по JSON (`entries`, `candidates`) и коду выхода, а не по тексту. В CI достаточно проверять код выхода: `2` — известное нарушение CRAP, `3` — ошибка анализа, `4` — неверные параметры.

## Настройка

Файл `.ub-mode.yaml` в корне проекта необязателен. Минимальный пример:

```yaml
version: 1
project:
  source: [src]
  exclude: [vendor, tests]
crapper:
  threshold: 10
  coverage:
    path: coverage.xml
dryer:
  threshold: 0.82
reports:
  directory: .metrics
```

Остальные ключи и их значения по умолчанию — в [`.ub-mode.yaml`](../.ub-mode.yaml). Неизвестные ключи считаются ошибкой. Другой файл настроек: `vendor/bin/ub-php --config путь.yaml check`.

## Мутационное тестирование (по желанию)

Запускает **тесты вашего проекта** много раз, поэтому делается только явно и может быть долгим. Тесты выполняются с их обычными побочными эффектами.

```sh
composer require --dev infection/infection:0.29.14 phpunit/phpunit:^11.5
# настройте infection.json5 в корне проекта (пример: fixtures/mutation/)
vendor/bin/ub-php doctor --tools
vendor/bin/ub-php mutate --changed --min-msi 80
```

- Другие версии Infection не поддерживаются. CDMU ничего не устанавливает сам.
- `--min-msi 80` — минимальная доля убитых мутантов. Ниже порога — код 2.
- Если порог задан, а измерить MSI нечем (например, нет подходящих мутантов), результат — `FAIL` с кодом 3, а не тихий успех.
- Результат — `.metrics/mutate.json`. После ошибки там может лежать прежний результат: ориентируйтесь на код выхода текущего запуска.
- Служебные файлы тестов (отчёты PHPUnit, `tests/tmp`) могут мешать: см. `mutator.input_exclude` в [руководстве](README.ru.md#cli).

## UML (по желанию)

```sh
vendor/bin/ub-php uml
# затем откройте .metrics/uml.html в браузере
```

Работает без сервера и интернета, код проекта не запускает. Нужная часть схемы: `uml --namespace 'App\Domain'`. Схема — снимок: после правок создайте её заново. `--changed` для UML не поддерживается.

## Частые вопросы

| Симптом | Причина и решение |
| --- | --- |
| `no PHP files found in configured source directories` (код 3) | Нет каталогов `src`/`app` или в них нет PHP. Задайте `project.source` |
| `--changed requires a Git repository` (код 3) | Каталог не в Git-репозитории. Уберите `--changed` |
| Всё `unknown` | Нет `coverage.xml` — см. выше |
| `invalid command or option` (код 4) | Опечатка в параметре. Общие опции `--root` и `--config` ставятся **до** команды |
| `mutate` сообщает об отсутствии `vendor/bin/infection` | Infection не установлен; см. раздел про мутации |
| Результат мутаций «устарел» (stale) в UML | Исходники, тесты, bootstrap или их конфигурации изменились после `mutate`; запустите `mutate` заново |
