# CDMU: руководство пользователя и интеграции

[English version](README.md)

CDMU проверяет CRAP и структурное дублирование PHP, интегрирует необязательное мутационное тестирование и создаёт автономный UML. `check` выполняет C+D; `mutate` и `uml` запускаются отдельно. Навык агента `ub-mode` поддерживается в соседнем репозитории. Краткий разбор для начала — в [инструкции](GUIDE.ru.md).

## Требования, совместимость и происхождение

Composer-пакету нужны PHP 8.2+, Composer 2 для установки и расширения PHP DOM, JSON и MBString. Зависимости времени выполнения: `nikic/php-parser` 5.x, Symfony YAML/Process 7.4 и `colinodell/json5` 3.x (MIT). Git нужен только для `--changed`. Python и Docker не требуются. Лицензия репозитория — MIT, парсера — BSD-3-Clause, Symfony YAML — MIT. Алгоритмы и форматы EDN Crapper и Dryer изучались по исходным репозиториям с лицензией 0BSD; их код сюда не скопирован. При распространении сохраняйте уведомления о лицензиях зависимостей.

Парсер проверен на чистом PHP и небольших синтаксических образцах Laravel, Symfony и Yii. Это не полноценные приложения фреймворков. Возможность парсера принять более новый синтаксис не равна версии PHP, на которой запускается инструмент. Проект пока не заявляет поддержку Windows или точное покрытие ветвей.

Поля Crapper EDN `:entries`: `:name`, `:namespace`, `:complexity`, `:coverage`, `:crap`. Экспортируются именованные функции и методы; замыкания, стрелочные функции и методы анонимных классов остаются только в JSON, потому что исходный viewer не сопоставит их синтетические имена. Отсутствующие покрытие и CRAP записываются как `nil`, в отличие от исходного значения 0% при отсутствии отчёта; это требование нашей спецификации. Dryer EDN использует `:candidates` с оценкой, языком `"php"`, диапазонами строк и числом узлов. JSON — основной формат интеграций. В первоначальной v0.1 M/U отсутствовали; эта версия добавляет адаптер Infection и самостоятельный автономный UML-просмотр PHP.

### Необязательный runtime M/U

Адаптер поддерживает Infection 0.29.14, отдельно устанавливаемый в проект. Настоящий fixture закрепляет PHPUnit 11.5 в lock-файле и проверен на PHP 8.2 с Xdebug coverage. Для M требуются POSIX/PCNTL и группы процессов Linux/macOS; выполняемые тесты сохраняют свои обычные побочные эффекты. PCOV поддерживается самим engine, но эта интеграционная матрица проверялась с Xdebug. Совместимость с другими релизами Infection и произвольными test-framework конфигурациями не заявляется.

C/D/U не выполняют целевой PHP и не требуют Infection/coverage extension. UML использует php-parser и встроенные HTML/JS/SVG без Java/CDN/Graphviz. Это автономный просмотрщик с ограниченным набором функций, а не полная копия upstream UML Viewer. Новые схемы M/U независимы; совместимость с upstream M/U EDN не заявляется. Symfony Process и JSON5 имеют MIT-лицензию; Infection имеет BSD-3-Clause и не включён как обязательная runtime-зависимость.

## Установка

До публикации добавьте рабочую копию как Composer path repository из целевого проекта. Путь должен существовать в той среде, где запускается Composer:

```sh
composer config repositories.ub-cdmu-php path /path/to/ub-cdmu-php
composer require --dev yatseck-k/ub-cdmu-php:@dev
vendor/bin/ub-php doctor
vendor/bin/ub-php check
```

Для разработки пакета выполните `composer install`, `composer test` и `composer test-consumer` в его корне. Для настоящего интеграционного прогона установите зависимости в `fixtures/mutation/`, включите Xdebug coverage и выполните `php tests/mutation.php --integration`. Пример конфигурации: [`.ub-mode.yaml`](../.ub-mode.yaml).

## Команды и конфигурация

Запускайте `vendor/bin/ub-php` из корня анализируемого проекта. Глобальные параметры `--root PATH` и `--config PATH` указываются перед командой. `doctor` проверяет PHP, доступность парсера и YAML-зависимости и каталог проекта. `check` запускает включённые проверки Crapper и Dryer; `crap` и `dry` запускают по одной. Каждая команда принимает `--format text|json`; команды проверки принимают `--changed`, а `crap` и `dry` также `--threshold NUMBER`. Параметр `--changed` включает добавленные и изменённые PHP-файлы из индекса Git, рабочего дерева и неотслеживаемых путей в настроенных каталогах.

### Прогресс и текстовый отчёт

После `check`, `crap`, `dry`, `mutate` и `uml` доступны `--progress auto|always|never` и `--verbose`. Для `doctor` эти флаги не применяются. В режиме `auto` (по умолчанию) текстовый запуск пишет прогресс в stderr: бар в терминале, отдельные строки при перенаправлении. JSON по умолчанию не пишет прогресс. `always` включает stderr-прогресс и с JSON, `never` отключает его. JSON stdout остаётся пригодным для обработки программами.

Четыре стадии C/D: разбор PHP, расчёт CRAP, сравнение дубликатов, сохранение отчётов. Проценты относятся к указанной стадии. Отключённые и пустые стадии помечаются skipped. `Completed` означает завершение анализа и записи настроенных отчётов, включая запуск с замечаниями; это не PASS. При ошибке Completed не выводится. Перерисовка терминала ограничена по частоте, лог обновляется с шагом 10%.

Обычный текст показывает до 10 нарушений CRAP по убыванию значения, 5 записей с неизвестным покрытием по убыванию сложности и 5 групп DRY по 3 совпадения. Для скрытых элементов указаны количество и способ раскрытия через `--verbose` или полный JSON, если он включён. `--verbose` выводит все CRAP-записи и совпадения. JSON/EDN всегда полные. Сходство DRY — предупреждение, а не доказательство взаимозаменяемости кода.

Итог содержит число файлов и единиц кода, известное/неизвестное покрытие, нарушения, пары/группы DRY, реально сохранённые пути и следующие действия:

- `PASS`, код `0`: замечаний в проверенном объёме нет.
- `WARN`, код `0`: неизвестное покрытие, DRY, нарушение CRAP при отключённом fail_on, отсутствие изменённых файлов или включённых проверок.
- `FAIL`, код `2`: CRAP достиг порога при включённом quality.fail_on.
- Ошибка анализа возвращает `3` с диагностикой в stderr; текстовый режим также сообщает FAIL и незавершённость анализа. Ошибка вызова возвращает `4`.

Unknown не означает проверенное соблюдение CRAP-порога. Пустой --changed не оценивает весь проект. Старые отчёты не подтверждают успех текущего запуска. Для тихого stderr в текстовом режиме используйте `--progress never`.

```sh
vendor/bin/ub-php check
vendor/bin/ub-php check --verbose --progress never
vendor/bin/ub-php check --format json --progress always > result.json
```

Текстовый отчёт разделён на блоки, пути отчётов выводятся отдельными строками. В терминале заголовки голубые, PASS зелёный, предупреждения и unknown жёлтые, FAIL и нарушения CRAP красные. Цвет отключается при перенаправлении, установленной переменной `NO_COLOR` или `TERM=dumb`. Для прогресса определяется терминал stderr, для отчёта — терминал stdout.

### Конфигурация

Необязательная `.ub-mode.yaml` использует `version: 1`; пример находится в репозитории. Каталоги `project.source` используются, только если существуют. Полное C/D-сканирование без PHP-файлов возвращает аналитическую/конфигурационную ошибку с кодом 3; `--changed` без изменённых PHP-файлов завершается успешно с пустым отчётом. Пути из `project.exclude` исключаются на любом уровне дерева. `crapper.coverage.path` указывает на готовый отчёт Clover XML. Если его нет, покрытие остаётся неизвестным. По умолчанию отчёты пишутся в `.metrics/`. Статические check/crap/dry/uml не запускают тесты и не изменяют исходники. Явная mutate передаёт выполнение тестов Infection.

Коды выхода C/D: `0` — анализ пройден (в том числе при предупреждениях Dryer или неизвестном покрытии); `2` — известный CRAP достиг порога; `3` — ошибка среды, конфигурации, разбора или отчёта; `4` — неверные параметры CLI. JSON детерминирован при неизменных входных данных. Git нужен только для `--changed`; вне Git-репозитория команда завершается кодом `3` и сообщением `--changed requires a Git repository`, поэтому там параметр не используйте.

### Необязательное мутационное тестирование

Обычный `check` выполняет C+D. Infection устанавливается отдельно в проект с готовыми PHPUnit-тестами:

```sh
composer require --dev infection/infection:0.29.14 phpunit/phpunit:^11.5
# Сначала настройте Infection и bootstrap/source вашего PHPUnit-проекта.
vendor/bin/ub-php doctor --tools --format json
vendor/bin/ub-php mutate --changed --min-msi 80 --format json
vendor/bin/ub-php mutate --verbose
```

Проверенная комбинация: PHP 8.2, Infection 0.29.14, PHPUnit 11.5 и Xdebug coverage. Engine также может использовать PCOV; интеграционные проверки выполнены с Xdebug. Для завершения группы процессов mutate нужны POSIX и PCNTL на Linux/macOS. Другие версии Infection считаются неподдерживаемыми. Для C/D/U эти компоненты не нужны. `doctor --tools` сообщает доступность engine, UML, coverage extension и управления процессами, не запуская тесты; обычный doctor совместим с прежним форматом. Наличие расширения само по себе не подтверждает включённый coverage mode.

Секция `mutator` в `.ub-mode.yaml`: `executable` (по умолчанию `vendor/bin/infection`), `configuration` (`infection.json5`), `threads` (1), `process_timeout` (600 секунд), `min_msi` (null), `input_paths` / `input_exclude` (пустые списки), `keep_failed_runs` (5). Infection-конфиг JSON/JSON5 должен находиться непосредственно в корне проекта: относительные пути сохраняют смысл. Пример — `fixtures/mutation/`. Собственные source directories/excludes Infection остаются в силе, а точный список CDMU дополнительно ограничивает scope. Тесты и bootstrap выполняются с обычными правами и побочными эффектами проекта. Исходники и пользовательский конфиг не перезаписываются; рабочие мутанты находятся в собственном временном каталоге. Имена файлов с запятой отклоняются как непредставимые в фильтре engine.

`--changed` использует staged/unstaged/untracked как C/D; без Git опустите параметр. Infection продолжает выполнять baseline-тесты. `--min-msi N` принимает 0..100 и перекрывает mutator.min_msi. Заданный порог включает gate этой команды независимо от quality.fail_on для C/D. Собственные minimum-score флаги Infection переопределяются для сбора результатов; код CDMU определяется его собственным minimum.

Коды mutate: 0 — запуск завершён (PASS или WARN); 2 — известный MSI ниже порога; 3 — отсутствует/не поддерживается engine, не прошли baseline-тесты, timeout, изменились входные файлы, некорректный отчёт или ошибка записи; 4 — ошибка вызова. Выжившие/непокрытые/ошибочные/зависшие мутанты остаются находками даже при коде 0. Без эффективных мутантов MSI равен null. Без minimum это WARN/0; при заданном в CLI или конфиге minimum — FAIL/3, в том числе для пустого changed scope. Обязательный gate не оценён: failure-артефакт сохраняет gate_evaluated=false, а прежний успешный snapshot не заменяется. MSI и covered MSI различаются; timeout/error не переименовываются в killed.

Для завершённого результата без обязательной оценки JSON stdout содержит полный mutate envelope с FAIL, exit_code=3 и gate_evaluated=false — те же байты, что retained failure.json. Предыдущий опубликованный snapshot сохраняется. Реальный код процесса и диагностика текущего запуска важнее старого mutate.json. Ошибки до корректного результата (baseline/parser/I/O) сохраняют stderr и могут оставлять stdout пустым.

Результаты: `.metrics/mutate.json` (сводка, мутанты, scope, fingerprints), `mutate.raw.json`, `mutate.log`. Текст показывает до 10 находок, --verbose раскрывает всех мутантов. Прогресс: подготовка, Infection, чтение результатов, сохранение. Во время Infection показывается прошедшее время без выдуманных процентов. Timeout/прерывание останавливает группу процессов и удаляет временный конфиг и каталог мутантов. После публикации успешный run-каталог удаляется: raw и log уже входят в опубликованном поколении. Ошибочные запуски сохраняются в `.mutation-runs/` с ограничением mutator.keep_failed_runs.

Пути Infection `./src`, `src/` и `.` нормализуются с сохранением границ проекта. Дополнительные настоящие test inputs задаются через mutator.input_paths, временные данные вроде tests/tmp — через input_exclude; source и обязательные конфиги остаются защищены даже при совпадении с исключением. Logging/coverage targets и cache из PHPUnit XML исключаются автоматически, в том числе до появления файлов. Новый или изменённый настоящий тест продолжает инвалидировать run. Живой supervisor удерживает идентичность session до очистки. Guardian в собственной группе следит за закрытым контрольным каналом и убирает работников при смерти supervisor; engine не наследует endpoint владельца. Исторический PID не используется для сигналов. Лог и хвост ошибки читаются после остановки группы и дочитывания pipes, включая сообщения при TERM. Ошибка создания run откатывает свою частичную директорию; недоступный rollback сообщает оставшийся путь. При смерти машины или одновременном уничтожении всех защитных процессов userspace-очистка не гарантируется.

```yaml
mutator:
  input_paths: []
  input_exclude: [tests/tmp]
  keep_failed_runs: 5
reports:
  keep_generations: 5
```

### Автономный UML

```sh
vendor/bin/ub-php uml
vendor/bin/ub-php uml --namespace 'App\Domain' --format json
# Откройте .metrics/uml.html локально в браузере.
```

Команда создаёт полный статический граф и `uml.json`, `uml.svg`, `uml.html`. Infection, сервер, CDN, Java, Graphviz и Node на runtime не нужны. Доступны поиск, фильтры namespace, детали класса/членов, подсветка соседей, pan/zoom/reset и клавиатура. `uml.view_limit` по умолчанию 200 видимых узлов: скрытое количество указано, поиск достигает остальных узлов. JSON всегда полный. `--namespace` задаёт начальный вид; --changed отклоняется, чтобы не терять связи.

Извлекаются классы/интерфейсы/traits/enums, видимость, promoted properties и объявленные типы; связи extends/implements/trait-use/type/new/static-call с разрешением aliases. DI, magic, динамические зависимости и docblock-типы не угадываются. Анонимные классы пропускаются с явным счётчиком; дубли FQCN дают WARN и ambiguous-узел с перечнем всех определений. Его метрики неизвестны; неоднозначные исходящие связи пропускаются с диагностикой вместо выбора одного определения. После изменений UML нужно пересоздать.

Свежий CRAP считается без тестов по текущему коду и существующему Clover, включая явно настроенный внешний симлинк. Отсутствующее, нечитаемое или некорректное необязательное покрытие даёт unknown и предупреждение в diagnostics, сохраняя граф. M-overlay принимается только из управляемого snapshot с совпавшими source/test/config fingerprints и полным source scope. Устаревшие, вручную импортированные, несовместимые данные отмечаются stale/unavailable. Unknown окрашен нейтрально. Клики viewer не запускают тесты и не изменяют код. Код 0 означает успешное построение (возможно WARN), а не прохождение quality gate; для CRAP используйте check/crap. Ошибка синтаксиса PHP или записи возвращает 3 и сохраняет прежние артефакты. Повреждённый/нечитаемый необязательный M-snapshot считается unavailable, несовпадение inputs/version — stale. Неожиданные внутренние исключения остаются ошибками с кодом 3.

M/U сохраняются неизменяемыми наборами в `.metrics/.cdmu/`, с публичными symlink и атомарной сменой указателя. При переносе сохраняйте ссылки либо копируйте HTML/SVG с разыменованием. По умолчанию reports.keep_generations=5 оставляет текущее и четыре последних прежних поколения на инструмент; 0 отключает очистку. Публикация и чтение защищены exclusive/shared tool-lock. Активные runs не удаляются; оставленный без владельца свободный lock старше 60 секунд переводит run в ограниченную историю ошибок. Неуправляемые каталоги, симлинки и старые runs без метаданных владения сохраняются. Ошибка очистки — отдельное предупреждение, не отменяющее опубликованный отчёт. Публикация C/D не меняется. M/U всегда создают собственные JSON и вспомогательные артефакты; reports.formats управляет прежними C/D-экспортами.

## Правила расчёта метрик

### Crapper

Цикломатическая сложность каждой функции, метода, замыкания и стрелочной функции начинается с 1. Добавляется по 1 за каждый `if`, `elseif`, `for`, `foreach`, `while`, `do`, `catch`, вариант `case` или `match` кроме `default`, тернарный оператор, `&&`, `||`, логические `and`/`or` и `??`. Вложенные функции и замыкания получают собственную оценку. Абстрактные методы и методы интерфейсов без тела пропускаются.

Исполняемые строки задаются элементами Clover `<line type="stmt">` внутри границ единицы анализа включительно. Покрытие — процент строк с числом выполнений больше нуля; это покрытие строк, а не ветвей. Если отчёта нет, единица не сопоставлена с отчётом или у неё нет исполняемых строк, покрытие неизвестно. Для известного процента покрытия `P` используется формула `CRAP = CC² × (1 − P/100)³ + CC`. При неизвестном покрытии в JSON записывается `crap: null`, а в EDN — `nil`. Известное значение CRAP от 10 включительно не проходит проверку с порогом по умолчанию.

### Dryer

Кандидатами считаются только обычные функции и конкретные методы длиной не менее 4 строк исходного кода и с не менее чем 20 нормализованными узлами AST. Имена локальных переменных и литералы игнорируются; структура AST, операторы и имена прямых вызовов сохраняются. Сходство — отношение размера пересечения множеств признаков к размеру их объединения (коэффициент Жаккара). Порог отчёта по умолчанию — 0.82; кандидаты выводятся как предупреждения и не проваливают CI. При проверке агентом `ub-mode` можно явно задать 0.8. Замыкания и стрелочные функции не участвуют в сравнении на дублирование в v0.1.

Нормализация эвристическая: проверьте найденные пары перед рефакторингом. JSON содержит идентификаторы и дополнительные поля; `.metrics/crap.edn` следует [формату Crapper](https://github.com/unclebob/crapper), а `.metrics/dry.edn` — [формату Dryer](https://github.com/unclebob/dryer). Для совместимости с просмотрщиками EDN экспортирует только те поля и имена, по которым эти форматы могут сопоставить записи.

### Мутации и метрики UML

Счётчики берутся из JSON поддерживаемого Infection. Killed, survived, uncovered, timeout, error, syntax_error, ignored и skipped сохраняются раздельно. MSI, covered MSI и mutation coverage — разные проценты engine; их нельзя получать из Clover-покрытия CRAP. Без эффективных мутантов MSI неизвестен. Неизвестный MSI без minimum даёт WARN/0. При запрошенном minimum отсутствие оценки даёт код 3 и gate_evaluated=false в JSON stdout и совпадающем failure-артефакте. Minimum mutate не меняет quality.fail_on для C/D.

UML — снимок топологии, а не gate. CRAP класса: FAIL при нарушении измеренного метода, unknown при неизвестном покрытии хотя бы одного метода или отсутствии конкретных измерений, иначе PASS. Абстрактные члены не получают оценки. Mutation status берётся только из управляемого совпавшего snapshot: survived, incomplete для uncovered/timeout/error, killed для измеренных убитых мутантов, unknown при отсутствии сопоставленных мутантов, либо stale/unavailable. Зелёный CRAP не означает успешные мутации. После изменения source/test/значимых mutation-input настроек устаревшие значения не подставляются; параметры вида, форматы отчётов, retention и пороги гейтов не инвалидируют измерения.

## Архитектура и контракты отчётов

Статический C/D-анализ через `vendor/bin/ub-php` выбирает PHP-файлы в настроенных каталогах. Анализатор разбирает их с помощью `nikic/php-parser`, не загружая и не выполняя целевой код. В том же процессе PHP проверяется конфигурация, читается необязательный отчёт Clover, вычисляются CRAP и сходство Жаккара, применяются пороги и записываются отчёты JSON/EDN. Межъязыкового процесса и промежуточного JSON-протокола анализатора больше нет.

Единица анализа содержит устойчивый `id` на основе исходного кода, относительный POSIX-путь `file`, `namespace` (включая класс для методов), `name`, `kind`, границы строк включительно, `complexity`, `node_count` и нормализованные признаки AST `features`. В `id` входят путь и начальная строка; переименование или перенос единицы создаёт новый `id`. Канонический отчёт сохраняет поля `schema_version: "1.0"`, `tool`, `entries`, `candidates` и `diagnostics` для интеграций.

Отчёты сортируются и атомарно заменяются после успешного анализа. Ошибка разбора возвращает код 3 и сохраняет прежние отчёты. JSON — канонический формат, EDN экспортирует формы исходных инструментов. Каталог отчётов исключён из сканирования исходников.

### Контракты новых команд

Прежние check/crap/dry и обычный doctor сохраняют схему 1.0 и побайтовую совместимость. Новые команды имеют отдельные envelopes версии 1.0:

- mutate: tool, status, exit_code, engine (name/version), scope (changed/files), fingerprints (хэши source/inputs и эффективной конфигурации), summary, mutants, diagnostics.
- summary: total, killed, survived, uncovered, timeout, error, syntax_error, ignored, skipped, msi, covered_msi, mutation_coverage, min_msi, gate_evaluated. Без эффективного знаменателя оценка равна null.
- mutant: id, относительный POSIX file, положительный line, mutator, diff, status, unit_id: единственный самый внутренний span владеет вложенным мутантом. Равные/неоднозначные spans сохраняют null: Infection даёт строку, но не колонку. UML учитывает вложенные мутации один раз в классе и содержащем методе; null привязывается только к однозначному классу/методу с диагностикой. Проверяются счётчики, диапазоны, полнота групп и scope.
- uml: tool, status, scope (files/namespace/view_limit), nodes, edges, mutation_overlay, limits, diagnostics. Узлы имеют устойчивый FQCN id, вид, source span, флаги, members и metrics; внешние типы не имеют source file. Ребро содержит from/to/kind. JSON-граф не ограничивается размером начального вида.
- doctor --tools: tool=doctor-tools и tools с возможностями engine/UML/coverage-runtime/process-control. Probe не запускает тесты проекта.

MutationCommand координирует отбор и fingerprints; InfectionRunner владеет процессом, временным конфигом и очисткой; InfectionReport валидирует JSON закреплённого engine. Fingerprints охватывают отобранный source, Composer manifest/lock, Infection/PHPUnit-конфиги и bootstrap, testsuites из PHPUnit, существующие tests/test/spec/fixtures и явно заданные input_paths. Исключаются объявленные test outputs/cache, канонический reports.directory и input_exclude. Каждый выбранный файл хешируется один раз за снимок; общего обхода всех JSON/XML/PHP репозитория нет. Хеш конфигурации — версионированная проекция version, project.source/exclude и mutator.executable/configuration/input_paths/input_exclude. Сырые байты .ub-mode.yaml, параметры UML/CRAP/DRY, reports/retention, minimum, threads и общий process_timeout исключены. Значимые настройки повторно загружаются из активного config path после mutate. Комментарии и UI-настройки сохраняют свежесть, реальные inputs — инвалидируют. Старые версии fingerprints становятся stale. Смена reports.directory меняет место поиска, без автоматического переноса snapshots. Внешние тестовые ресурсы и состояние БД в эту границу не входят.

Topology отдельно извлекает структуру с NameResolver, не меняя единицы Analyzer. UmlCommand объединяет свежий CRAP с проверенным совпадающим M-snapshot; Viewer создаёт SVG и HTML со встроенными JSON/CSS/JS. Просмотр не запускает мутации и не редактирует код.

M/U публикуются неизменяемыми поколениями с checksum: под отдельным file lock подготавливаются публичные ссылки и атомарно переключается единый указатель в .cdmu/. Ошибка подготовки сохраняет прежний набор. Очистка ограниченной истории выполняется под той же блокировкой; shared reader-lock защищает snapshot на время чтения manifest и JSON. Реализация рассчитана на Linux/macOS, не Windows. Прежняя атомарная запись отдельных C/D-файлов не меняется, включая явно настроенный reports symlink во внешнее хранилище. M/U хранит отчёты внутри проекта; reports.directory="." остаётся недопустимым.

## История выпусков: черновик v0.1.0

Исторический черновик первоначального выпуска с C/D. Указанное ниже отсутствие M/U относится к тому черновику; текущая реализация включает мутации и UML, описанные выше.

- Composer-пакет и CLI только на PHP с версионированными отчётами JSON.
- Оценки CRAP по статической сложности и готовому покрытию строк Clover; отсутствие покрытия остаётся неизвестным.
- Предупреждения о структурном дублировании с настраиваемым порогом Жаккара и отчётами JSON/EDN.
- Выбор изменённых файлов и тесты CI на PHP/Composer. Примеры интеграции с агентами поддерживаются в отдельном репозитории `ub-mode-php`.

Известные ограничения: нет автоматического сбора покрытия, мутационного тестирования, визуализации UML и поддержки Windows. Проверка фреймворков использует небольшие синтаксические образцы. Этот черновик станет примечанием к выпуску после прохождения всех проверок v0.1.
